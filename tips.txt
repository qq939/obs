# VS Code Tips for Mac

1. **IntelliSense / Code Completion**:
   - Trigger suggestion: `Ctrl + Space` (or just type and wait)
   - Accept suggestion: `Tab` or `Enter`

2. **Navigation**:
   - Go to file: `Cmd + P`
   - Go to symbol: `Cmd + Shift + O`
   - Go to definition: `F12` or `Cmd + Click`

3. **Editing**:
   - Comment/Uncomment line: `Cmd + /`
   - Multi-cursor: `Option + Click`
   - Move line up/down: `Option + Up/Down`
   - Copy line up/down: `Shift + Option + Up/Down`

4. **Terminal**:
   - Toggle terminal: `` Ctrl + ` ``

5. **Emmet 快速补全（HTML/CSS）**:
   - 输入 `div.video-container` 按 `Tab` → 展开为 `<div class="video-container"></div>`
   - 输入 `ul>li*3` 按 `Tab` → 一次生成 3 个 li
   - 输入 `m10` 按 `Tab`（CSS 文件中）→ 展开为 `margin: 10px;`

6. **调试视频播放速率（本项目 -3x 倒放）**:
   - Chrome DevTools `Console` 里直接执行 `document.querySelector('video').playbackRate`
     查看当前速率；`= -3` 会让 Chrome 抛 `NotSupportedError`（故代码走兜底 seek）。
   - 想看原生负速率效果：Safari → 开发 → 显示网页检查器 → 控制台执行
     `document.querySelector('video').playbackRate = -3`。
   - 快速重跑集成测试：终端按 `Cmd + P` 输入 `task` 可跑 Task，或直接
     `python3 test_integration.py`（项目根目录）。

7. **抽象全局常量（本项目 url_head）**:

     可列出全部引用位置（对应 server.py 顶部注释里标注的行号）。

14. **排查后端「卡顿」的通用套路（本项目 /videos 阻塞事件循环为例）**:
   - 先用 `curl -w "%{time_total}\n" -o /dev/null <url>` 量每个接口耗时，找出慢的那一个
     （本项目 `/videos` 曾 2.3~3.1s）。
   - 再验证「是否阻塞事件循环」：并发打 N 个慢接口，同时发一个轻量接口（如 `/health`），
     看轻量接口是否被拖慢。本项目实测 `/health` 从 0.009s → **17.68s**，即确诊阻塞。
   - 根因模式：`async def` 路由里**同步调用**阻塞函数（`subprocess.run` / `time.sleep` / 大文件 IO）
     → 单线程事件循环被占满。修法：`await asyncio.to_thread(阻塞函数)`。
   - 重复计算要加缓存：本项目给 ffprobe 时长加了 `(路径, size, mtime_ns, HLS签名)` 为 key
     的进程级缓存，热缓存后 `/videos` 从 2.5s → 0.009s。
   - 冷启动也要快：用 `ThreadPoolExecutor` 并发跑未命中缓存的探测（4 路并发，
     28 次串行 ffprobe → 约 1s）。
   - 快速定位同步阻塞点：`Grep` 搜 `subprocess.run` / `time.sleep` / `open(` 是否出现在
     `async def` 路由体内。
   - 跑本任务测试：`python3 test_videos_concurrency.py`（含重启容器后的冷启动并发验证）。

15. **在 FastAPI 进程内做一个「每天固定时刻」的定时任务（本项目 04:00 生成 HLS）**：
   - 不引 APScheduler/Celery，用「后台协程 + 轮询 + 日期键去重」就够了：
     `lifespan` 里 `task = asyncio.create_task(loop())`，`yield` 之后 `task.cancel()` 并
     `await` 它（`with suppress(asyncio.CancelledError)`），否则容器重启会留悬挂任务。
   - **关键：日期键去重**。轮询是每 30s 一次，如果只判断「现在是不是 04:00」，
     30 秒窗口内会触发多次。做法：命中时返回 `'YYYY-MM-DD'` 字符串存到全局 `_last_key`，
     下次同一天直接跳过。这样即使容器在 04:00 之后重启，当天也不会重复跑。
   - 时区别用 `datetime.utcnow().hour == 4`（那是 UTC）。用 `zoneinfo.ZoneInfo("Asia/Shanghai")`
     做 `now.astimezone(tz)`；容器里可能没装 tzdata，要 `try/except` 回退固定 `timezone(timedelta(hours=8))`。
   - 可测试性：把「判断是否命中」抽成纯函数 `cron_key(now, tz, hour, minute)`，
     测试时**直接注入不同时间**验证边界（04:00 命中 / 03:59、04:01 不命中），
     不用真等到凌晨 4 点，也不用 mock 时钟。
   - 生成类任务要**幂等 + 原子**：产物先写临时目录 `.tmp-xxx` 再 `os.replace` 到最终目录，
     避免 ffmpeg 中断留下半成品；再配一个 `meta.json`（version+源文件 size）判断是否过期，
     这样「重复调用不重跑」既省时间又能被测试断言。
   - 别让定时任务和线上请求抢资源：`sweep` 用**串行**逐个跑 ffmpeg（不要并发多路），
     每个文件一把 `asyncio.Lock` 防重入。

16. **Python 踩坑：`from datetime import time` 会遮蔽 `import time` 模块**：
   - 症状：`AttributeError: type object 'datetime.time' has no attribute 'time'`
     （写 `int(time.time()*1000)` 时炸）。
   - 原因：`datetime` 模块里也有个 `time` 类，`from datetime import datetime, time, ...` 把它
     绑定到了 `time` 这个名字上，后面 `import time` 的模块名就被覆盖了（后 import 的才生效，
     若 import 顺序在 from 之前则被覆盖）。
   - 修法：**不要** `from datetime import time`；需要时间戳就 `import time` 用 `time.time()`，
     需要时间类型就 `datetime.time(...)` 全限定名。
   - 快速自查：`grep -n "from datetime import" xxx.py`，看见 `time` 就警惕。
   - 单元测试里让函数 `print` 出中间量（如 `print('MADE', made)`），
     断言关键子串，比只看 traceback 更快定位是哪一步炸的。

18. **网页「粘贴上传」怎么做（本项目首页新增的第三种上传入口）**：
   - **一个监听覆盖两种入口**：浏览器里「右键 → 粘贴」和 `Ctrl/Cmd+V` 触发的是**同一个**
     `paste` 事件，所以只需 `document.addEventListener('paste', ...)`，不用分别处理。
   - **拿文件两条路**：先看 `e.clipboardData.files`（Chrome/Edge/Safari 复制文件时会有），
     为空再遍历 `e.clipboardData.items` 找 `kind === 'file'` 的项调 `getAsFile()`。
   - **千万别无条件 `preventDefault()`**！纯文本粘贴时如果不放行，页面上的输入框
     （本项目公告板 `<textarea>`）就粘不进文字了。正确姿势：
     `const files = collect(e.clipboardData); if (files.length === 0) return; e.preventDefault();`
     验证方法：在浏览器里合成事件后看 `ev.defaultPrevented` 是 `true` 还是 `false`。
   - **剪贴板里的截图没有文件名**（`file.name === ''`），必须先兜底命名再上传，
     否则后端拿不到扩展名。按 `file.type` 映射扩展名，用
     `new File([file], name, { type: file.type })` 造一个带名文件即可。
   - **别重复造上传轮子**：把待确认文件存到模块级变量，确认后直接调用**已有的**
     `uploadFiles(files)`，小文件直传 / 大文件分片 / 秒传逻辑全部自动复用。
   - **一定要做「取消」的负向测试**：点取消后要用 HTTP 确认文件 **404**，
     只断言「弹窗消失」是不够的（可能已经偷偷上传了）。
   - 本机 `http://127.0.0.1` 也属于安全上下文（`isSecureContext === true`），
     但真实部署的 `http://<局域网IP>` 不是——`ClipboardEvent` 合成事件两种环境都能用于测试。
   - **Playwright 怎么模拟粘贴**：
     `const dt = new DataTransfer(); dt.items.add(new File([bytes], 'x.png', {type:'image/png'}));`
     `document.dispatchEvent(new ClipboardEvent('paste', { clipboardData: dt, bubbles: true, cancelable: true }));`
     然后 `page.locator('.paste-btn-ok').click()` 走真实点击。
   - 跑本任务测试：`python3 test_paste_upload.py`。

19. **前端「上传实时速度」怎么算才不跳变（本项目 3s 滑动窗口）**：
   - 别用「总字节 ÷ 总耗时」当实时速度——上传到后半程数字会变得非常迟钝。
     正确做法：**滑动窗口**，只保留最近 N 秒的采样点，用
     `(最新字节 - 窗口内最早字节) / (时间差)` 算瞬时速度；全程累计值另算作「平均速度」。
   - **样本要主动淘汰**：`while (samples.length > 2 && now - samples[0].t > window) samples.shift();`
     否则卡顿几秒后恢复，速度会被历史流量稀释，显示得极低。
   - **字节没增长时必须把瞬时速度归零**：否则「校验中」等不传数据的阶段会一直显示上一个假速度。
   - **时间源要可注入**（`sample(bytes, nowMs)`，缺省才用 `performance.now()`），
     这样能在 node 里用固定时间戳断言精确数值，不用 sleep 等真实时间。
   - 单元换算注意：`0 / 负数 / NaN` 应返回空串而不是 `0B/s`，避免 UI 出现怪异占位；
     `1024 → 1.0KB`、`1536 → 1.5KB` 这类边界一定要写进测试。
   - 跑本任务测试：`python3 test_upload_speed_and_threshold.py`。

20. **「整段校验」与「分段校验」怎么选（本项目 10MB 阈值）**：
   - **小文件（≤10MB）整段传 + 整段校验**：前端对**整个 Blob** 算一次 SHA-256 放请求头，
     服务端落盘后比对，不符就 `os.remove` 再报错。简单可靠，**绝不能留半成品文件**。
   - **大文件（>10MB）分片传 + 逐片校验**：每片单独算哈希放 `X-Chunk-SHA256`，
     服务端**落盘即校验**、不符立刻删掉该分片并返回 422；
     再配合 `/upload/init`（秒传 + 返回已传分片列表）与 `/upload/status`（枚举 `uploaded`）
     就能实现**断点续传**。
   - **一定要兼容旧客户端**：校验头「缺失」时不能直接拒绝，否则 `curl --upload-file` 全挂。
     策略 = 有声明才校验，没声明保持原行为（本项目就是这么做的，测试里专门有一条）。
   - 测试要点：错误哈希必须断言 **HTTP 4xx + 目标文件 404**（证明确实没落盘），
     只断言状态码是不够的。
   - 跑本任务测试：`python3 test_upload_speed_and_threshold.py`。

21. **「两个按钮格式保持一致」的正确做法：抽公共基类**：
   - 反例：两个按钮各写一套 `background/padding/border-radius/box-shadow`，
     改一个忘了另一个，视觉立刻不一致（本项目初始就是「描边 vs 实心」两种风格）。
   - 正解：把**所有视觉属性**集中到基类 `.panel-head-btn`，
     具体按钮只保留**差异部分**（本项目只有 `left: 12px` / `right: 12px` 左右定位）：
     ```css
     .panel-head-btn { border; background; color; font-size; font-weight; line-height;
                       padding; border-radius; cursor; box-shadow; transition; ... }
     .btn-delete-current { left: 12px; }
     .fab-upload        { right: 12px; }
     ```
   - **测试怎么断言「一致」**：
     ① 源码层：两个按钮都带同一基类；基类规则集包含全部视觉属性；
     ② 反向断言：各自规则集里**不允许再出现** `background/color/padding/...`，
        防止以后有人又塞回去；
     ③ 浏览器层（最硬的证据）：用 `getComputedStyle` 逐个属性比对两个元素，
        断言差异为空对象。本项目实测 18 项属性零差异。
   - Playwright 里做这件事的写法：
     `[...props].forEach(p => { if (a[p] !== b[p]) diff[p] = [a[p], b[p]]; })`，
     返回 `{ identical: Object.keys(diff).length === 0, diff }` 一眼看出差在哪。
   - 跑本任务测试：`python3 test_video_delete_button.py`。

22. **删除资源要「删干净」：文件 + 派生产物一起清**：
   - 本项目视频有派生数据（`hls/{filename}/` 分片目录）。只删原文件会留下
     **孤儿分片目录**，既占磁盘又可能被列表逻辑误命中。
   - 做法：删原文件后顺手 `shutil.rmtree(hls_dir/filename, ignore_errors=True)`；
     目录不存在就静默跳过（非视频文件本来就没有 HLS）。
   - 用 `await asyncio.to_thread(shutil.rmtree, path, True)` 而不是直接调用，
     避免大目录删除阻塞事件循环（这条是之前并发卡顿踩过的坑）。
   - 测试：真造一个视频 → 生成 HLS → 调 DELETE → 断言
     **原文件 404 + `/hls/...` 404 + /videos 列表不含**，三条缺一不可。
   - 跑本任务测试：`python3 test_video_delete_button.py`。

23. **让标题可点击跳转（本项目首页「文件托管服务」→ /video）**：
   - **先确认元素真的存在**！本项目首页只有 `<head>` 里给浏览器标签用的
     `<title>文件托管服务</title>`，**页面可见区域根本没有该标题**。
     无脑改 `title` 是没用的（标签标题不可点，也不该加 `<a>`）。
     排查手法：`curl -s http://host/ | grep -nE '<h1|<h2|标题文字'`，
     再看 `<body>` 之后有没有对应元素；Playwright 里 `document.querySelector('.site-title')`
     返回 `null` 就说明得先补元素。
   - 正确做法：在 `<body>` 内放真实标题并套链接：
     `<h1 class="site-title"><a href="/video">文件托管服务</a></h1>`。
   - **纯 `<a>` 会变成默认蓝色带下划线**，和「标题」观感冲突，要单独兜住样式：
     ```css
     .site-title a { color: #333; text-decoration: none; }
     .site-title a:hover { text-decoration: underline; }   /* hover 才给提示 */
     ```
   - 断言「像标题」而不只是「是链接」：测试里查 `.site-title a` 规则内
     **有 `color` 且 `text-decoration: none`**；只断言 `href` 会漏掉观感问题。
     注意别用 `.site-title[^{]*\{...\}` 这种宽正则，会先匹配到不含颜色的那条规则
     （本项目就踩了，改成正则精确锚定 `.site-title\s+a`）。
   - 端到端验证最硬的证据是**真点一下**：Playwright `page.locator('.site-title a').click()`
     然后断言 `page.url()` 变成目标地址，比只看 HTML 靠谱。
   - 跑本任务测试：`python3 test_home_title_link.py`。


## 把多个设置项塞进同一行（数量 + 两个开关）

- 原写法是「一项一个 `.setting-row`」= 每项各占一行；要合到一行，
  就把它们放进**同一个** `.setting-row`，里面再各包一个 `.inline-item`：
  ```html
  <div class="setting-row setting-row-inline">
      <span class="inline-item"><b id="videoCount">0</b></span>
      <span class="inline-item">随播<label class="switch">…</label></span>
      <span class="inline-item">自播<label class="switch">…</label></span>
  </div>
  ```
  父级 `.setting-row` 的 `display:flex; justify-content:space-between` 已能横向排布，
  子项只需 `display:inline-flex; align-items:center; gap:8px` 让「文字 + 开关」贴在一起。
- **复用容器时要覆盖继承来的样式**：`.setting-row b` 带 `max-width:60%; text-align:right`
  （本来是给文件名那种长文本用的），数字会被推到右边，得在更具体的选择器里改回来：
  ```css
  .setting-row-inline .inline-item b { max-width: none; text-align: left; word-break: normal; }
  ```
- 断言「同一行」不用截图也能测：**div 配对计数**取出那一行的 HTML 片段，
  确认三个控件都在片段内、且片段里只有 1 个 `<div`（多出来的 div 才可能换行）。
  再去掉标签看整行文本是否恰好等于期望的 `29随播自播`，比逐个 `in` 断言更严。
- 文案简化后记得**连注释一起改**：测试断言「页面不出现『视频数量』」时，
  自己写的 HTML 注释里带上那四个字也会把测试搞红。
- VSCode 提示：改 HTML 属性/标签可用 `Cmd + D` 选中同名片段批量改；
  `Cmd + Shift + L` 可以一次选中全部相同文本，改 `setting-row` 这类重复 class 很快。
